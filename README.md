# hxyfront-62005 管风琴音管调音记录（可续作现场维护版）

给管风琴维护人员使用的音管调音记录台。针对管风琴间经常无网络、多名技师在同一本维护工单上补记的场景，
支持**离线记录、恢复后合并、故障可续作**。可记录场馆、音栓、音管编号、音高、音分偏差、温湿度、
簧片状态、维修备注，并提供音栓列表、调音偏差表、异常音管标记和单次维护报告。

## 现场维护流程

1. **现场补记（离线）**：技师在「现场补记」页把音栓、音管、音高、音分偏差、簧片/备注、温湿度、异常标记、
   音栓复检组成一笔修改。每笔保存即获得 **设备序号（ST-A / ST-B …）+ 连续记录号（#1、#2…）**，号只增不复用。
2. **确认**：记录先落在「未确认」队列，可改可废；**未确认记录不进入单次维护报告，也不会同步**。
   确认后变为只读，离线时留在本机「已确认待同步」分区。
3. **网络恢复**：已确认记录自动续传并入工单，**按「音管编号 + 字段」合并**：
   - 两边改的是不同字段 → 各自保留；
   - 同一字段只有一边改过，或后写者已见过先写版本（版本向量覆盖）→ 因果覆盖；
   - **两名技师在同一基线上同时保存、同一字段两边都改过 → 两版同时保留**，在「工单合并台」列为冲突，
     由技师选定生效版本；裁决本身也带设备序号与记录号，走同样的确认/同步流程。
4. **单次维护报告**：门控条件全部满足才能生成——无未确认记录、已确认记录全部并入、无未裁决冲突、
   无被复检守卫拦截的解除。报告封存为带内容签名的快照。
5. **复检守卫**：异常音管被标记后，**音栓复检完成前解除一律无效**（解除挂起、音管保持异常并列入门控）；
   音栓复检记录并入后解除生效。
6. **温湿度联动**：每笔音分偏差绑定记录时的温湿度；当前温湿度偏离记录值超过 **±2°C / ±8%** 时，
   该偏差结论标红失效，新温湿度并入后旧报告签名变化，提示**旧报告需重算**。

## 可靠性（写盘失败 / 离线包损坏）

- 每条记录独立分区键 + 校验和，先写数据再写索引，无半截记录。
- **写盘失败**：未写入内容保留在内存并标红，可点「重新写入」；重试沿用同一批次 id 与记录号，
  成功后**不会重复增加维护次数**。
- **已确认记录只读且独立分区**：其它分区损坏不影响其读取，坏条在校验时被单独隔离，可「重建索引」。
- **离线包（U 盘 / 内网摆渡）**：导出带整包校验和；损坏或被篡改时整包拒绝，已有记录不受影响；
  重复包按批次 id 去重。
- 「同步与故障恢复」页提供写盘故障注入、损坏单条记录等演练按钮。

## 架构

```
src/
  types.ts     领域模型：Batch（设备序号+连续记录号+版本向量）、Entry、Resolution、ReportSnapshot
  merge.ts     纯函数合并引擎：版本向量因果归约、双版本冲突、复检守卫、气候失效、报告签名
  storage.ts   分区存储 + 校验和、写盘故障注入、离线包导入导出校验
  store.ts     状态中枢：序号分配、未确认/已确认队列、幂等同步、报告门控与重算判定
  Composer / Outbox / MergedView / ReportView / SyncPanel  五个操作界面
```

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62005
npm test           # 规则与界面测试
npm run build
```

内置两名技师（ST-A 陈技师、ST-B 林技师）和一份历史工单种子数据，可直接演练：
切换设备 → 断网各记一笔同一音管同一字段 → 恢复网络看双版本冲突 → 裁决 → 生成报告 →
再记一笔高温温湿度 → 查看旧报告「需重算」。

技术栈：React 19 + Vite + TypeScript。
